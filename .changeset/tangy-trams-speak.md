Each compile's `meta.dependencies` is what it read beyond its template, on top of what its template and tag lookups read (shared, not copied), as an opaque handle: `taglib.forEachDependency(dependencies, visit, seen)` calls `visit` with each path to watch and its kind (`"file"`, `"missing"` or `"directory"`), skipping the layers already in `seen`. `taglib.invalidate(paths, cache)`, given one path or several as one invalidation, marks stale what read a reported path (as `path.resolve` gives it, so relative and non-normalized paths match) and returns every template marked, whatever cache compiled it and whether or not its compile threw, dropping those `cache` holds, and `taglib.revalidate(cache)` does the same for every path changed on disk since it was read, which `@marko/compiler/register` runs once per tick. A caller that reports changes this way sets `reportsChanges`, and its compile cache hits read nothing from disk; for any other, a hit checks against disk, as before, the files the template and the templates its analysis loaded read, and the taglibs of its lookups. A tag lookup that fails to build (a malformed `marko.json`, a `tags-dir` or import not there yet) is kept until something it read or looked for changes, as one that built is, so the templates it failed are returned then too. `taglib.getDependencies(dirnames)` gives such a handle for what the tag lookups of some directories read with every tag loaded. Translators record what a compile reads with `taglib.addFileDependency(filename)` and `taglib.addDirectoryDependency(dir, names)`, the latter returning the entries of `dir` that `names` name. Nothing read in `node_modules` is recorded, as what is installed is taken not to change while the process runs: after an install a caller calls `taglib.clearCaches()`. A linked workspace package's files are recorded as the project's. `meta.watchFiles` and `meta.analyzedTags`, which integrations that predate `dependencies` read, are derived from it when first read, and `TaglibLookup.watchFiles` is removed. The compile cache is keyed by filename, so two projects compiled in one process with `optimizeKnownTemplates` no longer share the templates that get the same id.
