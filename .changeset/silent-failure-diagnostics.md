Two guided diagnostics for mistakes that previously failed silently or with a bare runtime error. A `<let>` whose variable is never assigned and whose initializer reads reactive values now emits a compile warning naming both readings and the fix: "captured once and will not update... use `<const/>` for a derived value that recomputes; keep `<let>` if a one-time capture of the initial value is intended." In observed agent-written code the accidental form was the single most common silent mistake, rendering correctly and then never updating; the intentional form (capturing a "first"/untracked value) is valid and the wording says so. The check does not fire for assigned lets, controllable lets, bound attributes (`value:=`), or static initial values. Keying a `<for>` by its own loop parameter (`<for|city| of=cities by=city>`) now fails at compile time with the property-string and function forms suggested, instead of dying at render with an undefined-variable error.
