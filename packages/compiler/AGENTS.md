# `@marko/compiler`

Translator-agnostic compiler: parses `.marko` into a Babel AST (custom node types like `MarkoTag`, `MarkoAttribute` — added to Babel by the root `patches/`), runs migrate/transform passes, then hands the AST to a **translator** (`@marko/runtime-tags/translator` or `marko/translator`) for codegen. Stays at v5.x; language changes belong in the translators, not here.

## Map

- All of `src` is TypeScript, checked by the package `tsconfig.json` against Marko's Babel types (`types` from `@marko/compiler`, `NodePath` from `@marko/compiler/babel-types`). There, `@marko/compiler/internal/babel` maps to `src/internal-babel.d.ts`, a typed view of its exports (never one the module lacks) that also corrects Babel's typings where the compiler relies on more (`traverse`'s `visitSelf` argument, `inputSourceMap: false`, `metadata.marko`); the published `internal/babel/index.ts` keeps stubbing Babel's packages so its consumers need none of Babel's typings. What the pipeline keeps on a template's file, its config and its tag nodes is typed in `src/util/compile-file.ts` (`CompileFile`, `MarkoOpts`, `FileOpts`, `TagNode`); code given Babel's file reads it as a `CompileFile` (`file as CompileFile`), a cast that compiles away. `src/register.cts` stays CommonJS, since requiring `@marko/compiler/register` must give the hook itself. The published `.d.ts` files at the package root stay hand-written.
- `src/index.ts` — public API: `compile[File][Sync](src, filename, config)` → `{ code, map, meta, ast }`, `configure`, `taglib`, `types`.
- `src/config.ts` — option defaults (`config.d.ts` declares every option), and the `globalConfig` that `configure()` sets (both re-exported by `index.ts`). A default read outside a compile's own config (e.g. `getRuntimeEntryFiles`, `taglib.buildLookup`) comes from `globalConfig`, never the default export.
- `src/babel-plugin/` — pipeline core. Stages: `parse → migrate → transform → analyze` (cached per template) then `translate` on a clone. Taglib visitors run in `migrate`, `transform` and `translate` — including those from the taglibs a translator registers via `taglibs`/`optionalTaglibs`, which is how a translator contributes migrators. The compiler runs the translator's `transform` and `analyze` (both optional) and `translate`; there is no `translator.migrate`. A tag definition's `analyze` hook runs only where the translator dispatches it (runtime-tags' `visitors/tag`); an `analyze` key at a `marko.json` root is ignored. Taglib `translate` is skipped for `output: "hydrate"`. With `stripTypes` (on for translated outputs), `strip-types.ts` strips TypeScript after `migrate` in one walk without Babel's traversal, compiling enums, namespaces and parameter properties and inlining constant enum members; only a template that may declare an enum or namespace (one's keyword before whitespace or a comment, or any unicode escape) hoists each scope's enum and namespace names, and the names hiding them, as the walk enters it. With `modules: "cjs"`, `commonjs.ts` converts the translated output in the plugin's `post`, after project Babel plugins, as Babel's loose mode did; both walk without paths and share `util/ast.ts`.
- `src/taglib/` — tag registry and discovery; `types.test.d.ts` checks its exports against the published `taglib` types. Resolution order is documented on `Registry` and `Layer` in `lookup.ts`. Invariants: finding a directory's lookup costs one `package.json` stat; a nearer definition never replaces one of the translator's own tags but merges into it, keeping its hooks (the interop relies on this for class components named like Marko 6 core tags); tag definitions keep only what something reads; each file system gets its own registries, and a compile passes its `fileSystem`; caches are dropped only whole (`clearCaches`, `register`, `excludeDir`, `excludePackage`), which only adding or removing files or editing JSON calls for, never editing a template.
- `src/babel-utils/` — the helper API for translator authors (`assert*`, `diagnostic*`, `import*`, `parse*`, `getTagDef`, `isNativeTag`, `resolveTagImport`, ...). Exported as `@marko/compiler/babel-utils`.
- `internal/babel/index.ts` — the single controlled Babel entry, re-exported as `@marko/compiler/internal/babel`. All Babel code (here and in translators) is reached through it, never `@babel/*` directly; `src` may still `import type` Babel's own types from its packages (`@babel/core`, `@babel/parser`), which compile away.

## Translator contract

A translator module exports `translate` (required visitor), `taglibs` (required, `[[id, props]]`), `tagDiscoveryDirs` (required), optional `transform`/`analyze` visitors, `optionalTaglibs`, `classTaglibs` (applies the class API taglib rules in `taglib.ts` › `loadClassTagDir`; defaults to `tagDiscoveryDirs.includes("components")`), `preferAPI` (`"tags"` | `"class"`), `version`, `getRuntimeEntryFiles(output, optimize)`, and `cheatsheet` (module-relative path to an LLM syntax reference). `config.translator` selects it, else `config.ts` detects it from the app's dependencies (`util/try-load-translator.ts`, whose `Translator` types the contract).

## Notes

- `output: "source"` / `"migrate"` re-print `.marko` source (tooling/codemods) — no translator codegen.
- Bumping any `@babel/*` version requires regenerating the corresponding patch in root `patches/` (pnpm patchedDependencies); the custom AST types and generated `dist/types.d.ts` (`pnpm --filter @marko/compiler run build-babel-types`) depend on them.
- `util/agent-fix-guide.ts` appends a pointer to the translator's `cheatsheet` to compile errors when it detects a coding-agent environment (`CLAUDECODE`, `AI_AGENT=1`, …); `MARKO_AGENT_FIX_GUIDE=0` suppresses it and any other value forces it. It fires only for a translator given as a module id, so fixtures compiled with an inline translator object snapshot the same under an agent; a test of the guide forces it (`packages/runtime-tags/src/__tests__/main.test.ts` › `forceCodingAgent`).
- A compile `cache` keeps each template as analyzed (parse through `analyze`), keyed by translator and template id and revalidated against its content and the watched files of it and every template its analysis read (`hasStaleDependency`). `meta.analyzedTags` lists the templates whose analysis the compile read for its output: for a template, those its own analysis loaded (not what they read in turn); for a page entry, every template the entry reaches. A bundler plugin walks the lists in reverse from an edited template, transitively, to compile again every template whose output follows it (`@marko/vite`). Configs may share one only when they differ in `output` alone, as the bundler plugins' do: nothing before `translate` may read `output` or import an output-specific runtime path. Omitting `cache` uses one process-wide Map (`src/config.ts`), so a test compiling under several configs gives each its own `cache: new Map()`.
