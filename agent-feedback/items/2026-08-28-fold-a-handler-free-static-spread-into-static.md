# Fold a handler-free static object-literal spread on a native tag into static attributes

The `t.isMarkoSpreadAttribute(attr)` branch of `analyze.enter` sets `valueExtra.isEffect = true; hasEventHandlers = true; hasDynamicAttributes = true` without ever inspecting the value, and `hasEventHandlers` is what sets `getProgram().node.extra.isInteractive`, so a fully static object literal marks the program interactive and registers the element for resume. `<div ...{ "data-a": "1" }>hi</div>` server-renders 862 bytes under `NODE_ENV=production`, a 22-byte page plus an inline resume `<script>` and a `<!--M_*1 a-->` marker, with no client code and `diagnostics = []`, while the same attribute written literally renders 22 bytes and a genuinely dynamic `<html data-x=input.x>` renders 37 with no script and no marker, so it is the spread branch rather than dynamism that pulls in resume. The debug scope reason names it outright: `"EventAttributes:#div/0": ["...{ \"data-a\": \"1\" }", "1:9"]`. Folding is already possible with the helpers in hand: `evaluate()` is already imported and applied to plain attribute values in the same attribute loop, `packages/compiler/src/babel-utils/compute.js › computeNode` has a full `ObjectExpression` case and no method or function-expression case at all, so a confident result provably carries no handlers and the pairs can be emitted as static attributes. The foldable set is narrow, since `computeNode` resolves no identifiers, so `...CONST`, `...input.attrs` and `...(cond && { a: 1 })` all stay as they are; `packages/runtime-tags/src/__tests__/fixtures/controllable-select-dynamic-spread` already carries three handler-free `<option ...{ value: "a" }>` spreads and records the resume output in its snapshots, so the fix regenerates those.

Check: `pnpm run compile -- -o html -d <dir>/spread.marko` on `<div ...{ "data-a": "1" }>hi</div>` emits `_attrs({ "data-a": "1" }, "#div/0", $scope0_id, "div")`, `_el_resume(...)` and `_script(...)`, where `<div data-a="1">hi</div>` emits a single `_html("<div data-a=1>hi</div>")`. Rendering both through `@marko/compiler/register` configured `{ translator: "@marko/runtime-tags/translator", output: "html" }` under `NODE_ENV=production` gives `literal 22 hasScript=false hasMarker=false` against `spread 862 hasScript=true hasMarker=true`, and a dynamic `<html data-x=input.x>` control gives `37 hasScript=false hasMarker=false`. Visible in-tree without a scratch file: `grep -n _el_resume packages/runtime-tags/src/__tests__/fixtures/controllable-select-dynamic-spread/__snapshots__/html.bundle.js`.
