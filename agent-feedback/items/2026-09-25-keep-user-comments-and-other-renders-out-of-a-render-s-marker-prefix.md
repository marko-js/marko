# Keep user comments and other renders out of a render's marker prefix

Every render's inline walker (`html/inlined-runtimes.debug.ts` › `WALKER_RUNTIME_CODE`) walks the whole document and claims any comment starting with its prefix, while `_escape_comment` knows only the `State.commentPrefix` of the render it writes into and sees one placeholder at a time. So the prefix is left unescaped in static comment text (`translator/core/html-comment.ts` › `escapeCommentText` escapes only `>`), whether it stands alone (`M_$1 #text/1`) or is followed by a placeholder (`M${"_$1 #text/1"}`), and an embedded render's value that spells the page render's prefix is adopted by the page render. Escaping each placeholder on its own also rewrites values that do not start the comment (`x${"M_a"}` renders `<!--x&#77;_a-->`), which no walker could claim. Two runtimeIds can also give renders one prefix (`M`+`a_` and `Ma`+`_` both write `Ma_`), and `dom/resume.ts` › `init` compares renderIds only among the renders of its own runtimeId, so that overlap is never reported. Direction: have `html-comment.ts` escape the comment's leading run, static text included, as one value and leave later placeholders to the `>` escape; decide whether that escape should break any leading `runtimeId` + word characters + resume symbol (covers every render of the runtime, at the cost of mangling ordinary comments such as `Mom's`).

Check: `pnpm run compile -- -o html -d` on a file holding `<html-comment>M_$1 #text/1</html-comment>`, `<html-comment>M${"_$1 #text/1"}</html-comment>` and `<html-comment>x${"M_a"}</html-comment>` emits `<!--M_$1 #text/1-->` as written, `<!--M${_escape_comment("_$1 #text/1")}-->` and `<!--x${_escape_comment("M_a")}-->`. A fixture with `embed.marko` holding `<html-comment>${"M_$1 #text/1"}</html-comment>`, a template `<let/count=0/><button onClick() { count++ }>${count}</button><div>$!{Embed.render({ $global: { renderId: "embed" } }).toString()}</div>`, `skip_csr: true` and steps `[{}, click]`: the click throws `Cannot read properties of null (reading 'data')` from `_text`. `node -r ~ts` a script in the repo root that renders `_template("t", () => { const id = _scope_id(); _html(_text_resume(id, "#text/0", "a")); _scope(id, { v: 1 }); }, 1)` (imports from `./packages/runtime-tags/src/html.ts`) with `$global: { renderId: "a_" }` and with `$global: { runtimeId: "Ma", renderId: "_" }`: both write `<!--Ma_$1 #text/0-->`.
