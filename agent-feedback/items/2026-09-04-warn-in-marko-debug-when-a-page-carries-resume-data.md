# Warn in MARKO_DEBUG when a page carries resume data the DOM runtime never initialized

A client bundle built from a plain `output: "dom"` compile never becomes interactive, with zero diagnostics: the SSR page ships correct HTML plus the inline bootstrap that parks resume payloads on `self[runtimeId]`, and nothing consumes them, because `init()` is emitted only by the compiler's entry builder, reached only via `entry: "page"` — which `packages/runtime-tags/src/translator/visitors/program/index.ts` rejects with ``The "entry" option requires the `linkAssets` compiler option to be configured`` — or the deprecated `output: "hydrate"`. No `linkAssets` implementation ships outside this repo's own test bundler, so anyone integrating Marko 6 with their own bundler lands here, and nothing signals it anywhere on the path: `init` carries no JSDoc, no repo-owned doc names it, `packages/compiler/config.d.ts` declares `entry?: EntryKind` with no comment at all, and its `output` deprecation note steers readers from `"hydrate"` to `output: "dom", entry: "page"` without mentioning that the second throws without `linkAssets`. Add a `MARKO_DEBUG`-guarded check that, at document `load`, walks the render entries on `self[DEFAULT_RUNTIME_ID]` and warns once when any has pending resume data and was never initialized, matching the precedent `readyFailed` sets in this same file for the analogous "server-rendered content cannot become interactive" failure so production compiles no call site; a non-default `runtimeId` yields a false negative rather than a false positive, a static SSR page emits no bootstrap at all, and `template.mount()` never writes `self[runtimeId]`, so the two legitimately non-interactive shapes cannot trigger it. Pair it with JSDoc on `init`/`initEmbedded` and a `linkAssets`-required note on `entry` in `packages/compiler/config.d.ts`.

Check: Compile a `counter.marko` (`<let/count=0/>` plus `<button onClick() { count++ }>Count: ${count}</button>`) from the same source path twice, with `pnpm run compile -- -o dom -d` and `-o html -d`, so the registry ids match; the dom output contains no `init` call. Bundle the dom output as an IIFE with `var MARKO_DEBUG = true;` prepended, load it as an inline script after the rendered SSR HTML in jsdom with `runScripts: "dangerously"`, and dispatch a click: the text stays `Count: 0`, the console is empty, and `window.M._.r` still holds its resume entries. The same bundle plus `import { init } from "@marko/runtime-tags/debug/dom"; init();` counts up and drains `M._.r`.
