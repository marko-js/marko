# Add `<search>` to the native-tag registries and reconcile them with `Marko.NativeTags`

`packages/compiler/src/taglib/marko-html.json` holds exactly 111 tag keys, the current HTML element set minus `search`, `slot`, `fencedframe` and `selectedcontent` plus the obsolete `param`, so `<search>` (in the Living Standard since 2023) fails to compile with an edit-distance typo suggestion and is missing from `packages/runtime-tags/tags-html.d.ts › Marko.NativeTags` too. The two registries also disagree in both directions: `slot`, `discard` and `feDropShadow` are typed but not compilable, while `param`, `animateColor` and all 42 MathML tags are compilable but untyped, and untyped means unchecked, since `<div bogusattr="x"/>` is an `mtc` TS2353 while `<param bogusattr="x"/>` passes. Nothing generates one list from the other or diffs them, so both drift silently. Add `search` to both and pin the divergence with a test that diffs the three JSON taglibs against `NativeTags`; keep `slot` out of the compiler list, where `packages/runtime-tags/src/translator/visitors/tag/custom-tag.ts › knownWrongTags` deliberately gives it a curated hint, and update `packages/runtime-class/test/taglib-lookup/fixtures/getTagsSorted/expected.json` as `packages/compiler/AGENTS.md` requires. Attached request: obsolete but universally parsed elements (`center`, `font`, `marquee`), which HTML email still needs, are absent by policy, yet `<center>` reporting ``Did you mean `<meter>`?`` reads as a typo report, so a `deprecated` flag or a `knownWrongTags` entry should point at the `marko.json` `"<center>": { "html": true }` registration that the TypeScript reference documents only for custom elements.

Check: `pnpm run compile -- -o html -d /tmp/t.marko` on `<body><search><input type="search"></search></body>` reports ``Unable to find entry point for [custom tag](https://markojs.com/docs/reference/custom-tag#relative-custom-tags) `<search>`. Did you mean `<select>`?``; `<center>` suggests `<meter>` and `<font>` suggests `<form>`, while `<param>` compiles. Registry diff: the `"<...>"` keys of `packages/compiler/src/taglib/marko-{html,svg,math}.json` against the `NativeTag<` keys of `packages/runtime-tags/tags-html.d.ts` give d.ts-only `{discard, feDropShadow, slot}` and json-only 44 entries `{param, animateColor, math, mi, mo, ...}`. Type gap: in a project with `@marko/type-check` 3.2.0, `npx mtc` errors TS2353 on `<div bogusattr="x"/>` and exits 0 on `<param bogusattr="x"/>`.
