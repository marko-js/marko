# Say a tag-variable type annotation does not constrain writes, and name `<let<Type>/x=init>` as the way to type state

A TypeScript annotation on a tag variable (`<let/x: T = init>`) parses and compiles, but it does not constrain writes: it is checked against the initializer at the declaration and then ignored, so later assignments are checked against the type inferred from that initializer rather than the annotation, because extraction emits the annotated `const` as a separate statement while `packages/runtime-tags/tags/let.d.marko`'s `Input<T, K>` infers `T` solely from `value`. So `<let/x: unknown = 1>` rejects `x = "a"` with "Type 'string' is not assignable to type 'number'" — naming a type that appears nowhere in the source — while `<let/x: { a: number } = { a: 1, b: 2 }>` does flag `x.b`, and `<let/s: Set<string> = new Set()>` fails outright with TS2322 at the declaration; a union annotation is not even parseable, since `<let/x: string | null = null>` is a `CompileError: EOF reached while parsing expression` at the `|`. The spelling that gates assignments correctly is the tag type argument, `<let<Type>/name=init>`, and it is named nowhere in this repo: the cheatsheet's Golden rule 2 mentions only the TS2322 half and steers to `<let/s=(new Set<string>())>`, which cannot express widening, and its TypeScript section covers `Input<T>` but never how to type state at all. Say in the TypeScript section that a tag-variable annotation types the read and not the write and that `<let<Type>/name=init>` is how a `<let>` is typed, and put the same one-line JSDoc on `Input<T, K>` in `packages/runtime-tags/tags/let.d.marko`, the declaration an editor hovers. Making the annotation contextually type the initializer would mean changing extraction in marko-js/language-server, but the preventive signal — cheatsheet plus the shipped `.d.marko` stub — is owned here.

Check: In a project linking this tree's `packages/runtime-tags` as `marko` alongside `@marko/type-check`, `npx mtc -d condensed` over `<let/x: unknown = 1>` with `<button onClick() { x = "a" }>` reports `TS2322 Type 'string' is not assignable to type 'number'`, and over `<let/s: Set<string> = new Set()>` reports `TS2322 Type 'Set<unknown>' is not assignable to type 'Set<string>'`, while the same handler under `<let<unknown>/x=1>` produces no diagnostic. `pnpm run compile -- -o html -d /abs/t.marko` on `<let/x: string | null = null>` throws `EOF reached while parsing expression` at the `|`, and on the annotated forms the translator strips the annotation entirely (`let s = new Set();`).
