# Render a falsy dynamic tag's `content=` attribute instead of dropping it

`_dynamic_tag`'s `render` closure ends `if (renderer) { ... } else if (content) { return content(); }`, where `content` is the body argument the translator passes, never `inputOrArgs.content`, so a `content=` attribute is silently dropped when the tag name is falsy: `<${undefined} content=Slot/>` renders `""` while `<${"div"} content=Slot/>` renders `<div><b>slot</b></div>` and a template renderer gets the whole input object forwarded. The string-name branch of the same closure does read it (`content || normalizeDynamicRenderer(input.content)`), which is the entire asymmetry, and both documented halves of the expectation are in place, since the language reference states that a falsy dynamic tag name outputs the tag's content only and the native-tag reference states that native tags accept body content as a `content=` attribute. The client runtime drops it the same way, `packages/runtime-tags/src/dom/control-flow.ts › _dynamic_tag` passing `normalizedRenderer || (getContent ? getContent(scope) : undefined)` while the compiled dom output hands `content` through the `getInput` callback with no `getContent` at all, so a fix must move both halves together or it introduces a hydration mismatch. The html side is one `|| normalizeDynamicRenderer(inputOrArgs?.content)` in the falsy branch; the dom side is larger, because the `if (normalizedRenderer)` guard means `getInput()` is never called for a falsy name, so the input read has to be hoisted above `setConditionalRenderer`. Neither the compiler nor `mtc` reports anything on the shape, and no fixture combines a falsy name with `content=`, since `dynamic-tag-sometimes-null` and `dynamic-tag-null-after-content` both use the body form.

Check: in a scratch project on marko 6.3.46, `t.marko` = `<define/Slot><b>slot</b></define>` plus `<${input.tag} content=Slot/>`, then `node -r @marko/compiler/register -e 'const t = require("./t.marko").default; Promise.all([t.render({ tag: undefined }), t.render({ tag: "div" }), t.render({ tag: null }), t.render({ tag: false })]).then((r) => r.forEach((x) => console.log(JSON.stringify(x.toString().split("<script")[0]))))'` prints `""`, `"<div><b>slot</b></div>"`, `""`, `""`. The same template with a body, `<${input.tag}><i>body</i></>`, prints `"<i>body</i>"` for `undefined`. Compiled shape, from `pnpm run compile -- -o html -d <file>`: `_dynamic_tag($scope0_id, "#text/0", input.tag, { content: Slot }, 0, 0, ...)`, with the body argument `0`.
