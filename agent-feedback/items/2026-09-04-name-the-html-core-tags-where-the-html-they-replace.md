# Name the `html-*` core tags where the HTML they replace silently disappears

`packages/runtime-tags/cheatsheet.md` opens with "Marko 6 = HTML superset", yet two HTML constructs a developer writes into a template never reach the output, and on the paths a developer actually lands on the `html-` prefixed core tag that would emit each one goes unnamed. A bare `<script>` whose body happens to parse as JavaScript becomes a reactive effect contributing nothing to the SSR HTML — no element, no inline code, no diagnostic, exit 0 — so a pasted analytics or bootstrap snippet vanishes from server output and runs only if a client bundle later resumes the effect; separately, `packages/runtime-tags/src/translator/visitors/comment.ts` drops every `MarkoComment` with a bare `comment.remove()`, leaving no trace of `<!-- -->` and nothing on any of the compiler's four diagnostic channels. `packages/runtime-tags/src/translator/core/script.ts` already appends `htmlScriptTagAlternateMsg` on its html-attribute, tag-variable and non-text-child paths, which leaves uncovered precisely the two paths someone writing HTML-native markup lands on — the body-parse failure, where `parseStatements` rethrows Babel's raw `Missing semicolon.` for a `type="application/ld+json"` body without naming `html-script`, and the valid-JavaScript case — and that constant's link points at the `#script` anchor, the effect tag, while telling the reader to use `html-script` instead. Wrap the `parseStatements` call so its failure carries `htmlScriptTagAlternateMsg`, repoint that link, replace this tag's `autocomplete` description (today only "Use to create side effects.") with one naming the alternative the way `core/html-script.ts` already points the other way, add a Golden-rules line stating that `<!-- -->` is a source comment erased at compile time and that `<html-comment>`/`<html-script>` emit the real thing, and JSDoc `packages/runtime-tags/tags/html-comment.d.marko`, the only core-tag stub with no leading doc comment. Do not add a heuristic diagnostic on either construct: gating a `<script>` warning on the body reading no reactive bindings would fire on `packages/runtime-tags/src/__tests__/fixtures/basic-effect-no-deps/template.marko`, a first-class mount-once effect, and for comments the only unambiguous output-intent marker is the IE conditional comment, which `<html-comment>` cannot reproduce because it escapes `>` to `&gt;`.

Check: `pnpm run compile -- -o html -d /abs/page.marko` on `<div>hello</div>` followed by a `<script>` whose body is `window.dataLayer = window.dataLayer || []; console.log("analytics loaded");` exits 0, emits `_html("<div>hello</div>")` plus `_script(scopeId, registryId)`, and `grep -c dataLayer` on the output prints `0`; the rendered SSR HTML contains no trace of the body either. The same command with `type="application/ld+json"` and a JSON body reports Babel's `Missing semicolon.`, naming neither the tag nor `html-script`, while the `src=` attribute path does name it. On a `<div>` wrapping `<!-- keep me -->` it emits `_html("<div></div>")`. `grep -ci 'html-script' packages/runtime-tags/cheatsheet.md` and `grep -ci comment packages/runtime-tags/cheatsheet.md` both print `0`, and `head -1 packages/runtime-tags/tags/html-comment.d.marko` is `export interface Input {}`.
