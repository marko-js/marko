# Build same-program known-tag contracts from settled analysis

For a self-recursive template (`visitors/tag/custom-tag.ts › analyze`) and every `<define>` call (`visitors/tag/dynamic-tag.ts › analyze`), `knownTagAnalyze` runs mid-analysis: `getBindingPropTree` prunes the params binding before its reads settle, and `contentSection.returnSerializeReason` is read before `finalizeReferences` sets it. Translate then works from the settled tree, and the mismatch breaks three shapes: a recursive tag variable from `<return=n>` is written by HTML with no text marker while DOM wires `_var_resume`, so a click after resume throws in `_text`; a recursive template with `<const/{ label }=input/>` after its recursive call throws "`$if_content__input_depth._` is not a function" in CSR; and a `<define>` body holding an unused `<const/x=[input]/>` moves the call site's input update into `$setup`, so it never updates. Direction: record only call-site facts during traversal and build the prop tree, known exprs, `varExpr` and param reason groups at program analyze exit before pruning; an interim fix for the tag-variable case treats an unset same-program `returnSerializeReason` as forced. When settling, note `setBindingDownstream` keeps one value-expression entry per binding (the last call site's), which `pruneBinding`'s pure-value drop and `getValueInputs` read. This also removes the reason `analyzeAttrs` excludes same-program tags from `invokeOnly` ("Propagate invoke-only inputs into same-program `<define>` tags").

Check: `pnpm run compile -- -o dom -d` on `<let/count=0/><define/Foo|input|><const/x=[input]/><span>${input.n}</span></define><Foo n=count/><button onClick() { count++ }/>` emits `_let("count/2")` with no update function and calls `$Foo_content__input_n(..., $scope.count)` from `$setup`; delete the `<const>` and the call moves into `$count`. Fixture with `tags/rec.marko` = `<let/n=0/><if=input.depth><rec/child depth=input.depth - 1/><span>${child}</span></if><button onClick() { n++ }>${n}</button><return=n/>`, template `<rec depth=1/>` and a step clicking the first `<button>`: both ssr modes fail with "Cannot read properties of undefined (reading 'data')" in `_text`. Fixture with `tags/rec.marko` = `<if=input.depth><rec depth=input.depth - 1 label=input.label/></if><const/{ label }=input/><span>${label} ${input.depth}</span>`, template `<rec depth=input.depth label="x"/>` and steps `[{ depth: 1 }, { depth: 2 }]`: debug csr fails with that TypeError.
