# Warn in MARKO_DEBUG when an update is dropped into an already-caught `<try>`

Once `@catch` renders, `renderCatch` destroys the `<try>`'s content branch and its subscriptions, so assigning a fresh promise to the awaited value is dropped: the DOM stays frozen on the error branch while surrounding state keeps updating. The identical assignment in the identical template updates normally when no error occurred, so a retry button looks correct, runs its handler, resolves its fetch, bumps its own state — and simply never re-renders, with nothing logged, thrown, or type-checked; the closure's target scope set is empty, so the update reaches nobody. The only statements of the rule are an internal comment above `renderCatch` and one line in `packages/runtime-tags/cheatsheet.md`, neither of which a developer debugging a frozen UI reaches (markojs.com's core-tag reference omits the recovery semantics entirely, and that page lives in the website repo). The signal that fires at the moment of loss is a `MARKO_DEBUG`-only diagnostic on the dropped path: mark the owner scope in `renderCatch` when a catch destroys a content branch, and in `_closure` (`src/dom/signals.ts`), when a signal fires with no live target scopes on a marked owner, `console.error` that `@catch` cannot recover in place and the boundary must be re-rendered (e.g. by bumping a key on a wrapping `<for>`) — the same shape as the existing debug-only `_global_read` diagnostic. Back it with a one-line JSDoc on `Input.catch` in the shipped `packages/runtime-tags/tags/try.d.marko` stub, which `translator/core/try.ts` points `<try>`'s types at and which `.d.marko` tooling treats as TS, so the rule also surfaces on hover while the `@catch` is being written.

Check: Scratch template `/tmp/marko-scan/disco/try-retry-9f2/retry.marko`: `<let/attempt=0/><let/pending=Promise.reject(new Error("boom"))/><const/current=pending/>`, a `<button onClick() { attempt++; pending = Promise.resolve("ok " + attempt); }>`, `<div>attempt: ${attempt}</div>`, then `<try><@placeholder>loading</@placeholder><@catch|err|>error: ${err.message}</@catch><await|v|=current><div>value: ${v}</div></await></try>`. Then from the repo root: `env -u CLAUDECODE -u AI_AGENT MARKO_AGENT_FIX_GUIDE=0 pnpm run compile -- -o dom -d /tmp/marko-scan/disco/try-retry-9f2/retry.marko && node -r ~ts /tmp/marko-scan/disco/try-retry-9f2/run.mjs`, where `run.mjs` mounts the compiled module in a jsdom document, prints `root.innerHTML` after the initial rejection and after two button clicks. The control variant (`ok/ok.marko`, identical but starting from `Promise.resolve("first")`) prints `value: ok 1` / `value: ok 2` for the same clicks.
